# Документация приложения

Здесь только про десктопное приложение AniMori.

Юзерскрипт и версия для приставки живут в своих репозиториях
и документируются там же. Ветка `main` заморожена и хранит гибрид 2.x
таким, каким он был на последнем выпуске. Правило целиком: документация
описывает только свой продукт, а про соседний — ровно столько, сколько
нужно для решений в этом (`CONVENTIONS.md`, раздел «Документация»).

## С чего начинать

Два первых файла читаются до первой правки, остальные — по надобности.

| Файл               | Отвечает на вопрос                                              |
| ------------------ | --------------------------------------------------------------- |
| `REPO-LAYOUT.md`   | какие есть ветки, что в каждой лежит, как переносить правки ядра |
| `CONVENTIONS.md`   | по каким правилам живут код и документация                       |
| `ARCHITECTURE.md`  | как устроено приложение целиком: слои, мост, оболочка, экраны   |
| `STORAGE.md`       | где лежат данные, как работают снимок, выгрузка и облако         |
| `DATA.md`          | откуда берётся датасет названий и как он поставляется            |

Описание самого продукта — что умеет, чего не умеет, как собрать
и выпустить — в `README.md` в корне репозитория.

## Чего здесь не ищите

Перевод по словарю, шапка юзерскрипта, выкладка на Greasy Fork,
блокировщик рекламы, встраивание в чужую разметку и манга — не часть
этого продукта.

Снятые с эксплуатации документы гибрида 2.x здесь не хранятся — они
целиком есть в замороженном `main` и в вышедших релизах.

## Наследство в коде

Правил перевода глав и томов и ключей чужой читалки в ядре больше нет:
они убраны вместе с мангой.

Что осталось от юзерскрипта — куст ключей в `core/settings.ts`: внешние
ссылки (`set_link_rutracker`, `set_link_yummy`, `set_link_animego`
и домены к ним), перевод интерфейса (`set_interface`), блокировка
всплывающих окон и рекламы. Ключи читаются при загрузке настроек,
но что именно из них на что влияет в окне — сверяется по коду.
