# Устройство репозитория

Настольное приложение: интерфейс на Vue, оболочка на Rust через Tauri 2.
Этот файл — карта того, что где лежит.

## Ветки

| Ветка         | Что в ней                                      | Тег выпуска       |
| :------------ | :--------------------------------------------- | :---------------- |
| `app-3.0-dev` | настольное приложение со своим интерфейсом     | `app-<версия>`    |
| `main`        | история монолита 2.x, словарь перевода, сторож | `v2.0.2` и раньше |

Ветки самостоятельны: вливать одну в другую не нужно и нельзя.

### Почему main заморожен

В `main` лежит последний монолит 2.0.2 целиком. По нему восстанавливается
любой состоявшийся релиз, поэтому ветка не переписывается.

Одно правило обязательно: **`dictionary.json` остаётся в `main` навсегда**.
Словарь перевода клиент тянет по прямому адресу
`raw.githubusercontent.com/.../main/dictionary.json`. Перенесёшь или
удалишь — перевод отвалится сразу у всех установленных копий.

В `main` же лежит `watch-dataset` — ежедневный сторож датасета названий.
Собирает датасет не он: сборка живёт в `foulnike/animori-data`, а сторож
спрашивает три вещи: выходят ли выпуски, не застыло ли их содержимое
и не стареет ли карта номеров. Файл обязан лежать именно в `main`:
расписание работает только из ветки по умолчанию. В `app-3.0-dev`
держится его точная копия — чтобы сторож был виден там, где читают код.

## Что было уничтожено

Старая реализация десктопа — окно с самим сайтом anilist.co, в которое
сборка вшивала юзерскрипт. Убраны все её части: `hybrid.rs`, `adblock.rs`
со `src/shared/adblock/`, `proxy_guard.rs`, `capabilities/site.json`
и команда `animori_open_site`.

Туда же ушла отправка правок на сервер: `core/edit-queue.ts`
и `core/edit-sender.ts`. Список теперь односторонний — см. `STORAGE.md`.

Состоявшиеся релизы и теги 2.x не тронуты: артефакты скачиваются,
а установленные копии продолжают работать.

### Как старые копии переедут на 3.0

Сами. У нового приложения тот же `identifier` (`com.foulnike.animori`),
тот же ключ подписи и тот же адрес манифеста обновлений. Первый же релиз
`app-3.0.0` сдвигает `releases/latest`, и апдейтер старой оболочки видит
3.0.0 > 2.0.2. Настройки и токен лежат в том же профиле и подхватываются.

## Сборка

```bash
npm install
npm run dev:app      # передний край в браузере
npm run tauri:dev    # окно приложения
npm run tauri:build  # установщик
npm test             # проверки ядра
```

Режимов сборки больше нет: `vite.config.ts` один и безусловный.
`npm run build:app` сначала гоняет `typecheck:all`, потом собирает передний
край в `dist/app`. Его зовёт и `beforeBuildCommand`, и `beforeDevCommand`,
поэтому `tauri:dev` каждый раз пересобирает разметку целиком: сервера
разработки с горячей подстановкой в окне нет.

### Граница ядра

- `src/shared/` — ядро. Про свою оболочку не знает ничего.
- `src/app/` — надстройка: экраны, компоненты, роутер.
- `src-tauri/` — оболочка на Rust.

`npm run typecheck:shared` проверяет ядро в отдельности: в этой проверке
каталога `src/app` не существует, и любая стрелка из ядра в надстройку
ломает сборку. Граница важна: то же ядро живёт в соседних продуктах,
и перенос правки между ними дешёв только пока это так.

Правило трёх файлов: новый алиас ядра прописывается в `vite.config.ts`,
`tsconfig.json` и `tsconfig.shared.json`.

## Перенос правки ядра в соседний продукт

Ядро лежит здесь в `src/shared/`, а в скрипте — в `src/`, поэтому
`git cherry-pick` между продуктами не работает: правка переносится
патчем или файлом.

```bash
git format-patch -1 <коммит> --stdout > /tmp/fix.patch
git apply --directory=. -p3 /tmp/fix.patch   # подобрать -p под сдвиг путей
```

Правки в ядре стоит делать отдельными коммитами, не смешивая с правками
интерфейса.

Облачная часть, выгрузка в XML и плеер в юзерскрипт не переносятся: они
опираются на мост и файловую систему, которых в браузере нет.

## Выпуски

`app-<версия>` → `windows-latest`, компиляция Rust, установщик, подпись,
`latest.json`, портабл-архив.

Конвейер берёт описание релиза из верхнего раздела `CHANGELOG.md` и падает,
если номер в теге расходится с `package.json`.

## Мелкие следствия разделения

Файл разрешений теперь один — `src-tauri/capabilities/default.json`.
Вместе с окном сайта ушёл `site.json`, но разрешение
`allow-animori-reload` жило только в нём — его пришлось выдать главному
окну явно.

Прокси вырос в отдельный узел: настройка лежит в ядре (`core/proxy.ts`,
`core/proxy-settings.ts`), живая проверка — в `api/proxy-check.ts`,
а в интерфейсе у неё своя панель `ProxyBox.vue`. Запросы программы
подхватывают смену адреса сразу, а трафик самого окна — только с новым
процессом, поэтому перезапуск остаётся условием; просит о нём кнопка,
которая появляется лишь когда правка и вправду что-то изменит. Команда
у оболочки своя: `animori_restart`.

Здоровье источников считает `core/net-health.ts`, но это не выключатель,
а повод заговорить с человеком — после двух неудач подряд.
