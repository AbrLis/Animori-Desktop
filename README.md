# AniMori

Одно общее ядро и два приложения, собранные из него.

| Каталог | Что это |
| :--- | :--- |
| `packages/core` | Ядро: данные и правила без DOM, без экрана и без оболочки. Одно на все продукты |
| `apps/windows` | Настольное приложение под Windows |
| `apps/android-tv` | Приставка под Android TV |

Описание каждого продукта — в его каталоге: `apps/windows/README.md`,
`apps/android-tv/README.md`. Правила общие — в `apps/windows/docs/CONVENTIONS.md`.

## Почему так

Раньше ядро лежало копией в двух репозиториях. Отсюда шли две беды: правку надо было
вносить дважды руками, и она не доезжала. Из-за этого однажды приставка при разборе
облачной копии молча выбрасывала четыре поля — список человека терял часть данных, а
все проверки были зелёные, потому что в двух продуктах они проверяли разное.

Сейчас ядра ровно одно. Сторож расхождений, реестр и список «правки не доехали» больше
не нужны: расходиться нечему.

## Граница ядра

Ядро не знает ни про экран, ни про оболочку. Проверяет это `typecheck:shared` у каждого
приложения: в этой проверке надстройки не существует, поэтому любая стрелка из ядра
наружу роняет сборку.

Правило то же, что и раньше: **общий код не выбрасывают под продукт, который его
сейчас не зовёт.** Функция, не нужная приставке, может понадобиться телефону.

## Проверки

```bash
npm ci
npm test         # ядро, затем оба приложения
npm run typecheck
```

Зависимости собираются одним замком в корне: рабочие области npm поднимают всё
в `node_modules` рядом с ядром, которое живёт вне приложений.

## Выпуск

Выпускается по тегу, тег называет продукт: `windows-v<версия>` и
`android-tv-v<версия>`. Оба конвейера лежат в `.github/workflows` — GitHub читает их
только оттуда, а код каждого продукта им указывается отдельно.

Канал обновлений Windows держит собственный релиз `windows-latest`: адрес
`releases/latest` после появления здесь выпусков приставки уезжал бы на них.
